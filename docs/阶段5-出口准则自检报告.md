### 3.2 顺带发现并修掉的三个 A 级缺陷

这三条都是「一直坏着但没人会发现」的类型，写自动化断言的收益主要在这里：

| ID | 缺陷 | 为什么人工走查漏得掉 |
|---|---|---|
| D5-8 | 九页浏览器标签标题全是「AI学院联合作战平台」（SC 2.4.2） | 走查按页看，一次只看一页；标题重复要横向比才看得出。运营开五个驾驶舱对数据时才会难受 |
| D5-9 | 没有「跳至主内容」（SC 2.4.1） | 缺失的东西不在界面上，看截图看不出。只有真的用键盘从头 Tab 一遍才会察觉侧栏 11 项每页都要重按一次 |
| D5-10 | `/escalations` 有两个 `<main>` 地标（SC 1.3.1） | 视觉上完全正常，143 张基线一张都不会红 |

补跳过导航时特意用 `clip` 把它移出可视区而不是 `display:none`——后者拿不到焦点，等于没做；
也因此 131 张视觉基线**一张都没变**，加断言不用重做基线。

### 3.3 备份恢复演练（带压测数据实跑）

| 项 | 实测 |
|---|---|
| `pg_dump -Fc` | 退出码 0，1,367,605 字节，745 个对象条目 |
| 空库 `pg_restore` | 退出码 0，无报错输出 |
| 10 张表行数比对 | **0 张不一致**，含 `dtl_case_view` 100000 行、`dtl_attendance` 20000 行、`biz_course` 10001 行 |
| 结构 | `public` 表数 49 = 49；Flyway 最高版本 5.001；`calc_light` 在 dump 里（V-9 迁移可恢复） |
| BK2 附件增量 | 首次 `robocopy /MIR` 退出码 1（有拷贝），二次 0（无拷贝）；200MB 文件 SHA256 一致 |

选大表比对不是凑数：`pg_restore` 退出 0 也可能留下空表，只有行数逐表对上才敢说恢复成功。
同理 `robocopy` 退出码 0～7 全是成功语义，所以补了一次 SHA256。
