# 文档待修清单

代码与建表脚本里出现「已记入待修文档清单」的地方，指的都是这份文件。

**这份清单是干什么的。** 全程 AI 编码的模式下，实现与文档的偏差有两种处理方式：一种是当场按文档改代码，一种是当场按事实改文档。但还有第三种情况——**偏差本身需要人来裁决**：文档缺字段清单、两份文档互相矛盾、或者某个决定要等后面的阶段才有足够信息。这类偏差如果只写在代码注释里，等于消失了：下一次会话的 AI 读不到全部注释，人也不会去翻十几个文件的注释。写在这里，是为了让它们能被一次性验收。

**处理原则。** 每一条都必须落到「改文档」或「改代码」二选一，不允许长期挂着。列在这里的条目，实现侧已经选了一个能跑的做法并在代码注释里写明了理由——因此**不会阻塞开发**，但**会阻塞阶段验收**（人工验收时应逐条过一遍）。

## 二、需求文档缺字段清单（实现侧字段属推导，需人工确认）

需求文档的第 8–15 章按「页面与流程」组织，有几张明细表只出现在流程描述里，没有字段清单。这些表的字段是从需求的公式、页签或导入模板反推出来的——**推导本身可能对，但没有权威依据**，因此必须人工确认一遍。

| # | 表 | 依据 | 推导方式 |
|---|---|---|---|
| S-1 | `dtl_demand_review` 需求评审记录 | 需求 8.3.2 | 8.3.2 把评审字段挂在需求主表上，但 5.2.1 有「重新评审」转换（已评审 → 评审中），意味着一个需求会有多轮评审。按 8.3.2 的字段镜像 + 轮次建模：主表存当前值，本表存历史 |
| S-2 | `dtl_course_schedule` 课程排期 | 需求 9.9 | 9.9 只给了排期对象与上游依赖。注意课程排期不做排课三项校验，那只作用于培训场次创建（11.4） |
| S-3 | `dtl_session_attendee` 参训名单 | 需求 14.6 | 14.6 是导入模板章节，库侧字段清单属推导 |
| S-4 | `dtl_training_archive` 培训归档材料 | 开发 6.2.5 | 需求第 11 章只说培训归档是场次状态机的一个环节。按「归档材料 = 若干附件 + 说明」推导 |
| S-5 | `dtl_teaching_record` 授课记录 | 需求 15.3 | 字段由 15.3 的四个指标公式反推 |
| S-6 | `dtl_case_report` 总结报告 | 需求 12.6 | 12.6 描述的是页面与生成／编辑入口，没有字段清单 |

## 三、需要裁决的建模问题

| # | 问题 | 背景 | 风险 |
|---|---|---|---|
| M-1 | `dtl_teaching_record` 是否保留 | 讲师的授课记录与 `dtl_training_feedback` 存在职责重叠：前者服务 15.3 的授课次数与人次统计，后者服务评分统计 | 保留就必须守住两条纪律：讲师平均评分只读 `dtl_training_feedback`；学员反馈导入只写 `dtl_training_feedback`。否则会出现「两张表都写 → 平均评分重复计数」，正是 15.3 结尾警告的那类错误（试讲反馈 1 分与正式反馈 5 分不得平均成 3.0） |
| M-2 | `cfg_selfcheck_item` 的「是否必检」到底是什么 | 需求 13.9.3 写的字段是「是否必检」（布尔），但需求 9.4.1 的规则 CK2 说的是「勾选但未填说明视为未完成」，《课程自检CheckList初版》三给每一条都配了填写指引 | 已按后两者实现：`required BOOLEAN` 改为三态 `note_requirement`（无／选填／必填）+ `guide_text`（V1_010 迁移脚本）。**「是否必检」与「说明是否必填」是两件事**，合成一个布尔值会让自检流于形式。需求 13.9.3 的字段表应据此更正 |

## 四、纪律偏离（有明确原因，但要记账）

| # | 纪律 | 偏离内容 | 原因与补救 |
|---|---|---|---|
| P-1 | STK-1「前端 client 与枚举由 OpenAPI 生成，不手写」 | 前端 `shared/api/imports.ts`、`config.ts`、`meta.ts` 的 interface 目前是手写的，与后端 record 逐字段对齐 | 后端 springdoc 已就绪，缺的是生成器：`openapi-typescript` 无法在当前离线环境安装。**已守住 STK-1 真正要防的那一半——枚举取值一律从后端接口取，前端没有任何状态值／字典项／导入类型的字面量**（为此新增了 `/api/imports/types`、`/api/config/dicts`、`/api/config/selfcheck-items/note-requirements` 三个下发接口）。网络可用后用生成代码替换 interface 部分 |
| P-2 | 需求 13.8.2「每张模板卡显示最后更新日期」 | 模板卡上没有这一列 | 模板由后端按解析器的列声明**现场生成**，没有「文件更新日期」这个概念。真正对应的语义是「列定义的版本」，一期没有版本号。**不显示一个编造出来的日期**；若确需此信息，应先在需求侧定义模板版本号 |
| P-3 | 需求 13.8.3「超过 5000 行前端直接拒绝」 | 前端只校验扩展名与文件大小（20 MB），行数没在前端拦 | 行数要解析 xlsx 才知道，前端解析需引入 xlsx 库（离线环境装不了，且会让首屏包变大）。规则 I1 在后端强制执行，超限返回校验失败并写明行数。**后端拦得住，只是提示晚一步** |
