# 文档待修清单

代码与建表脚本里出现「已记入待修文档清单」的地方，指的都是这份文件。

**这份清单是干什么的。** 全程 AI 编码的模式下，实现与文档的偏差有两种处理方式：一种是当场按文档改代码，一种是当场按事实改文档。但还有第三种情况——**偏差本身需要人来裁决**：文档缺字段清单、两份文档互相矛盾、或者某个决定要等后面的阶段才有足够信息。这类偏差如果只写在代码注释里，等于消失了：下一次会话的 AI 读不到全部注释，人也不会去翻十几个文件的注释。写在这里，是为了让它们能被一次性验收。

**处理原则。** 每一条都必须落到「改文档」或「改代码」二选一，不允许长期挂着。列在这里的条目，实现侧已经选了一个能跑的做法并在代码注释里写明了理由——因此**不会阻塞开发**，但**会阻塞阶段验收**（人工验收时应逐条过一遍）。

## 三、需要裁决的建模问题

| # | 问题 | 背景 | 风险 |

### 顺带修掉的共用组件缺陷

| 组件 | 缺陷 | 修法 |
|---|---|---|
| `ActionGuard` | 外层 `inline-flex` 没开 `flexWrap`。P03 的「录入结论=不通过·修改后重新评审」有 15 个字，三个这样的按钮在 474px 的详情面板里排不进一行，多出来的被面板 `overflow:hidden` **裁掉** | 加 `flexWrap: 'wrap'`。被裁掉的按钮既看不见也点不到，表现和「这个动作不可用」一模一样，而**这类失效不报错**。P03 spec 里补了一条断言：五个按钮的右沿都不得越过面板右沿 |
| `ActionGuard` | 按钮间距写死 `space.md`。P02 四个动作里有个六字名（「录入评审结论」），四个按钮本身合计 380px，加 3×16px 间距后 428px > 410px 的面板正文，第四个换行（V2.0 是一行四个） | 开一个 `gap` 参数，默认仍是 `space.md`，P02 传 `space.xs`。**没有改动作名**——把「录入评审结论」缩成 V2.0 写的「录入结论」能省 26px，但界面上的动作名就和状态机转换表对不上了。P02 spec 补了一条断言：四个按钮的 `top` 必须一致 |
| `Chart` | `echarts.use()` 漏注册 `ScatterChart`。总看板四条效率折线的终点标注（圆点 + 日期 + 当期值）整批不渲染 —— **漏注册不报错**：ECharts 静默跳过未注册类型的 series，折线照画、SVG 计数照样是 4、控制台一片干净 | 补注册。p01 spec 加断言直接查这四个标注的文本 |
| `Chart` | 终点标注的锚点在绘图区右边缘，默认居中对齐时一半溢出被 SVG 裁掉，屏幕上是「06-1」「5.6 ヌ」这种缺字 | 标注改右对齐。断言不能只查 `textContent` —— 被裁的字在 DOM 里是完整的，那条断言照样通过。改成比几何：标注右沿不得越过 SVG 右沿 |
| 三页布局 | 设计稿几何是像素值，照抄成 CSS 后窗口一变宽，多出来的空间被布局引擎**随手分给某一个可伸缩元素**：写了 `flex:1` 的那一格独自变宽，宽度写死的那一行原地不动，同一页里一部分横带到边、一部分停在设计宽度。纵向同理，横带高度写死时窗口下方空一大片 | **全部改成按比例伸缩**（V-28）。横向用 `flex: 0 1 calc((100% - <间距>px) * <设计宽> / <设计宽之和>)`，纵向用 `flex: <设计行高> 1 0`。新增 `tests/visual/fluid.spec.ts`（4 条）—— 其余 spec 都在 1586×992 固定视口下跑，那里没有多余空间可分，完全测不到这一类问题 |
| P01 `.dash` | 第一版按比例伸缩写成 `flex: 1 1 auto`，页面下方空白没消掉，反而把最后一行顶出了视口 | basis 必须写 `0`。`auto` 意味着基准取内容测量值，入口卡插画按**自然高度**参与测量，一张 800px 高的插画让 R4 的基准比整个视口还高，四条横带的基准之和远超可用高度 |
| P04 台账 | 五行 22px 的表格实测 125px，比 R6 可用高度多出 10px。行内那枚「结论一致」的图标是 `inline-flex` + `vertical-align: middle`，**它把行盒从 20px 顶到 22px**（middle 对齐给行内块留出了下沉区），叠加 1px 内边距与 1px 分隔线后每行 25px | 图标改 `vertical-align: top`，`td` 显式写 `line-height: 20px` 并去掉纵向内边距（横向内边距只留首尾列）。这类偏差每行只有 3px，单行看不出来，**行数一多才越界**，而越界部分被 `overflow:hidden` 裁掉不报错 |
| P04 讲师卡 | 卡内四行指标与领域标签被压扁：标签行只剩 14px（设计 20px），文字上下被裁 | 卡的直接子元素都要显式 `flex: 0 0 <设计高>`。`flex-basis: auto` 下这些行的基准取内容测量值，容器一紧就按比例一起缩 —— 缩的是每一行，所以看起来「整体还在，只是都矮了一点」，比某一行消失更难发现。spec 补了一条断言直接量标签行与指标行的高度 |
| P01 中段 | 第二版横向写成 `flex: 499 1 0`，回归模式下预警区变成 519px，多出的 20px 从待办清单挤走，「业务对象」列掉到 144px | `flex-basis: 0` 在 `box-sizing: border-box` 下**仍被内边距与边框垫高**（12×2 + 1×2 = 26px），分配基准带了一截常量。改用百分比 basis（以容器内容宽为基准，与自身内边距无关）。另外 `min-width` 必须显式写 0 —— 默认值 `auto` 让 flex 项不能缩到 min-content 以下，三张预警卡的 min-content 合计 519px，会把同样的偏差带回来 |
