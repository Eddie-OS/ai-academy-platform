### 待业务裁决：三色灯语义前后端相反

后端按需求 13.4.1a **原文**实现，前端 V2 复刻件按 **V-9 新裁决**实现，蓝黄含义正好颠倒：

| 灯 | 后端 `calc_light` | 前端 V2 卡面文案 |
|---|---|---|
| 蓝 | 剩余 1～3 天，**即将到期** | 「正常运行 · 距预计完成时间 3 天以上」 |
| 黄 | **已逾期** | 「需要关注 · 距预计完成时间 3 天内」 |
| 红 | 仅状态停滞 | 「已超期或连续 5 天未变更」 |
| 无 | 计入 `healthy` | 「无预警」（算不出灯） |

后果是总看板产品模式 R5 区**每张卡的数字与它的副文案说的是相反的两件事**：蓝灯卡显示「快到期的对象数」却写着「还有余量」，黄灯卡显示「已逾期数」却写着「尚未逾期」。`panel-note` 的「健康 N」取后端 `NONE` 计数，里面装的是「剩余 0 天」与「没填预计完成时间」的对象。

`文档待修清单.md` V-9 原本要求需求 13.4.1a 的修订单**必须在阶段 3 开工前落到需求文档**，否则后端会照旧原文写——后端确实照旧原文写了，而修订单至今未落，本阶段提示词第 55 行也仍写着「不要把蓝灯当健康」。需求原文、业务裁决、提示词三方各执一词，**改任一侧都是推翻一个已生效的决定，须由业务定向后再动**。
