## P5 干扰测试记录

**已脚本化**，不再依赖真机人工勾选：[`scripts/perf/run-p5.ps1`](../scripts/perf/run-p5.ps1)。
分片上传放在 `Start-Job` 的独立进程里，主进程同时打总看板——串行地「传一片测一次」测不出
磁盘 IO 与连接池的相互挤占，而那正是这条要防的东西。

| 步骤 | 结果 |
|---|---|
| 200MB 源文件（前 4 字节 `PK\3\4`，过 F2 文件头校验） | 209,715,200 字节 |
| 申请上传 → 40 片 × 5MB（`COURSEWARE` 档，F1 上限 200MB） | ☑ |
| 传 3 片后中断，`GET /api/attachments/uploads/{id}` 回报已传分片 | ☑ `[0,1,2]` |
| 剩余 37 片续传（并发段） | ☑ 5.0s |
| 上传进行中并发打总看板 | ☑ 5 次采样 avg 678.5ms / **max 710ms**（限 3000ms） |
| 合并 + F2 真实类型校验 + 落元数据 | ☑ 3.4s，落库大小 209,715,200 字节与源文件一致 |
| 结论 | **达标** |

> 看板只采到 5 次样，因为并发段只有 5 秒。本机是 localhost + SSD，200MB 传得比生产快；
> 生产台式机上跑同一脚本采样数会更多，阈值判定逻辑不变。
