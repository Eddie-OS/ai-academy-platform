# 数据库备份恢复验证（E4-5）

> 依据：阶段 4 出口准则 E4-5、开发实施文档 5.11.1。  
> **「备份文件存在」≠「备份可恢复」。** 必须在空库上真正 restore 一次。

> **适用范围：本文全篇只适用于 Docker 形态。** 下面每一步都要 `pg_dump` / `pg_restore` / `psql`，
> 而单机交付包里这三个程序都没有 —— 嵌入式 PostgreSQL 只解包 `initdb`、`pg_ctl`、`postgres`。
> 单机形态的备份是手工停机打包 `data/` 目录，步骤见
> [`运维手册.md`](./运维手册.md) 的「单机形态没有自动备份」一节。

## 环境

- 生产部署：Windows + WSL2（BLOCK-05）
- 备份任务：`DatabaseBackupJob`，每日 02:00，`pg_dump -Fc`
- 默认目录：`./data/backup`（可用 `aiacademy.backup.dir` 覆盖）
- `pg_dump` 路径：`aiacademy.backup.pg-dump`（默认命令名 `pg_dump`）

## 验证步骤（PowerShell）

```powershell
# 1. 手动触发一次备份（或等定时任务），确认 dump 文件非空
Get-ChildItem .\data\backup\*.dump | Sort-Object LastWriteTime -Descending | Select-Object -First 1

# 2. 新建空库
$env:PGPASSWORD = '<password>'
createdb -h localhost -U postgres ai_academy_restore_test

# 3. 恢复
$dump = (Get-ChildItem .\data\backup\*.dump | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
pg_restore -h localhost -U postgres -d ai_academy_restore_test --clean --if-exists $dump

# 4. 抽查
psql -h localhost -U postgres -d ai_academy_restore_test -c "SELECT COUNT(*) FROM biz_demand WHERE deleted = FALSE;"
psql -h localhost -U postgres -d ai_academy_restore_test -c "SELECT COUNT(*) FROM dtl_escalation_record WHERE deleted = FALSE;"

# 5. 清理
dropdb -h localhost -U postgres ai_academy_restore_test
```

## 通过标准

- `pg_restore` 退出码 0（或仅有可忽略的 NOTICE）
- 抽查表行数与源库一致（或业务可接受的差异已说明）
- 本文件对应的人工验收动作在出口报告中勾选  
- **2026-08-04**：人工勾选 E4-5 = A（已 dump → 空库 restore → 抽查可读）

## 阶段 5 复演（2026-08-04，带压测数据）

阶段 5 又跑了一遍，这次库里有 10 万行浏览记录与 2 万行签到，比阶段 4 的空壳库更能说明问题。
逐条实测值记在 [`阶段5-生产初始化演练清单.md`](./阶段5-生产初始化演练清单.md) 的「备份恢复演练」一节，摘要：

| 项 | 结果 |
|---|---|
| dump 大小 / 对象数 | 1,367,605 字节 / 745 条 |
| 10 张表行数比对 | 不一致 0 张（含 100000 行与 20000 行两张大表） |
| 表数与迁移版本 | 49 = 49；Flyway 5.001；`calc_light` 在 dump 里 |
| 附件增量同步 | 二次 `robocopy` 退出码 0（无重复拷贝）；200MB 文件 SHA256 一致 |

> 补一句给下次做演练的人：**`robocopy` 的退出码 0～7 都算成功**，只看退出码判断不了同步是否真的完整，
> 这次是靠 SHA256 比对才敢说「一致」。同理 `pg_restore` 退出 0 也可能留下空表，所以行数比对必须逐表做。
